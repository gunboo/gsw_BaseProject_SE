# 로컬 월드 모니터링 시스템

게임에서 NPC와 몹 상태를 수집해 로컬 PC의 HTML 화면으로 확인한다. C++ 게임은 1초마다 전체 상태를 JSON으로 전송하고, Node.js 수신 서버가 프로젝트와 실행 인스턴스별 최신 상태를 보관한다. HTML 화면도 1초 간격으로 수신 상태를 조회한다.

현재 튜토리얼 마을과 제1레벨을 연결했다. 다른 프로젝트는 같은 JSON 규격으로 연결할 수 있다. 학기 종료 후 결정할 게임 통합 방식과 월드 이동 로직은 이 모니터링 인터페이스에 종속되지 않는다.

## 실행 방법

Node.js 18 이상이 필요하다. 별도 npm 패키지 설치는 필요하지 않다. `start-monitor.cmd`는 PATH의 Node.js를 먼저 사용하고, 없으면 이 PC의 Codex 번들 런타임 경로를 확인한다.

1. 저장소 루트에서 `Monitoring/start-monitor.cmd`를 실행한다. 명령줄에서는 다음과 같이 실행할 수 있다.

   ```powershell
   node .\Monitoring\server.js
   ```

2. 브라우저에서 [로컬 모니터](http://127.0.0.1:8765)를 연다. 수신 서버 콘솔은 열린 상태로 둔다. HTML은 서버 주소로 접속해야 실시간 상태를 받을 수 있다.
3. Visual Studio에서 `SimpleGame.sln`을 열어 x64로 빌드하고 게임을 실행한다. 게임 작업 디렉터리는 기존처럼 `SimpleGame`으로 설정해 `Data`와 `Shaders`를 읽을 수 있어야 한다.
4. 시작 화면에서는 NPC 상태가 정지로 표시된다. 플레이 중에는 고정 NPC가 대기 상태로 표시되고 대화 시 대상 NPC가 대화 상태로 바뀐다. 현재 게임은 인트로에서 `1`을 누르거나 튜토리얼 엔딩을 진행하면 제1레벨로 이동하며, 그때 마을은 비선택 상태가 된다.
5. 수신 서버를 종료할 때는 해당 콘솔에서 `Ctrl+C`를 누른다. 게임 또는 서버가 종료되면 화면에서 연결 상태를 확인할 수 있다.

게임을 먼저 실행해도 수신 서버가 시작되면 이후 스냅샷부터 연결된다. 서버가 꺼졌을 때 게임은 계속 진행된다. 송신 스레드는 게임 객체를 직접 읽지 않고 게임 스레드에서 만든 JSON 문자열만 전송한다. 송신 대기열에는 최신 메시지 한 개만 남긴다.

실제 `Monitoring` 폴더는 `SimpleGame.sln` 옆에 있다. Visual Studio 솔루션 탐색기에서도 `SimpleGame` 프로젝트 아래 `Monitoring` 필터로 화면·서버·실행 파일을 찾을 수 있다. 솔루션이 이미 열려 있다면 프로젝트 다시 로드를 적용한다.

## 화면에 표시되는 정보

| 표시 항목 | 의미 |
|---|---|
| 연결된 실행 인스턴스 | 최근 5초 이내 정상 메시지를 받은 게임 프로세스 수 |
| 선택된 월드와 로드된 월드 | 온라인 인스턴스에서 `active=true`인 월드 수와 메모리에 보관된 월드 수 |
| 상단 NPC 및 몹 수 | 온라인 인스턴스의 선택된 월드만 합산 |
| 월드 카드 | 선택 여부, 씬 상태, 맵 크기, NPC 수, 생존 몹 수, 몹 슬롯 수, 재생성 대기 수, 누적 처치 |
| 마을별 집계 | 해당 `villageId`에 속한 NPC와 몹의 수 및 소속 월드 상태 |
| NPC 상세 | 고유 ID, 마을, 행동 유형, 대기·대화·정지 상태, 월드 좌표 |
| 몹 상세 | 종류, 생존 상태, 체력, 위치, 재생성 대기 시간 |

현재 튜토리얼은 `Data/village.map`에서 읽은 NPC 8명을 `sanctuary` 마을에 배정하며 마을 몹은 없다. NPC 수는 실제 목록에서 계산하므로 데이터를 추가하면 집계에도 반영된다. 제1레벨은 몹 16개 슬롯을 가진 숲 월드이며, NPC와 마을은 등록하지 않는다. 몹을 처치하면 슬롯 수는 유지되고 생존 수가 감소하며, 재생성되면 생존 수가 증가한다.

현재 게임의 NPC는 지도에 지정된 위치에 고정되어 있으므로 `behavior`는 `stay`다. `state`는 플레이 중 `idle`, 대화 대상은 `talking`, 나머지 정지된 씬에서는 `paused`로 전송한다. 일반 NPC 체력 시스템이 없으므로 체력은 `null`로 전송하고 화면에는 `—`로 표시한다. 이전 확장 버전의 마을 AI와 외곽 몹 시스템은 현재 코드에 없으므로 가상의 이동 상태나 몹 수를 만들지 않는다. 외부 프로젝트가 보내는 이동·도주·복귀 상태는 화면에서 그대로 표시할 수 있다.

월드의 `active`는 플레이어가 선택한 씬을 뜻한다. 대화, 단서 목록, 능력치 화면에서도 선택된 월드는 `active=true`이며 실제 정지 여부는 `state`와 엔티티 상태로 확인한다. 튜토리얼에서 제1레벨로 이동한 후에도 메모리에 남은 마을을 `inactive`로 전송한다. 비선택 월드의 몹이 살아 있어도 해당 월드의 전투와 재생성 시간은 진행되지 않는다.

정상 메시지가 5초 넘게 도착하지 않으면 인스턴스를 오프라인으로 표시하고 상단 합계에서 제외한다. 마지막 상태 카드는 5분 동안 보관한다. 상세 표에서 오프라인 인스턴스를 보려면 **오프라인 포함**을 선택한다. 수신 서버 연결 자체가 끊기면 마지막 카드에 오프라인 표시를 적용한다. 수신 이력은 메모리에만 보관하므로 서버 재시작 후에는 새 메시지를 기다린다.

## JSON 메시지 규격

수신 주소는 `POST http://127.0.0.1:8765/api/snapshot`이다. `Content-Type: application/json; charset=utf-8`로 UTF-8 JSON을 전송한다. 한 메시지의 최대 크기는 2 MiB이며 압축 전송은 지원하지 않는다. 한 메시지는 한 실행 인스턴스에서 로드된 전체 월드를 포함한다.

완전한 요청 예제는 [example-snapshot.json](example-snapshot.json)에 있다. 예제는 별도 `sample-project` 인스턴스이며 실제 게임 상태를 나타내지 않는다.

| 필드 | 자료형 | 의미 |
|---|---|---|
| `schemaVersion` | 정수 | 현재 `1` |
| `type` | 문자열 | 현재 `snapshot` |
| `sourceId` | 문자열 | 프로젝트 또는 상태 제공자의 ID |
| `instanceId` | 문자열 | 실행마다 새로 만드는 세션 ID |
| `sequence` | 정수 | 실행 내에서 증가하는 메시지 번호, 1 이상 |
| `worlds` | 배열 | 로드된 전체 월드. 빈 배열도 허용 |

각 월드에는 다음 필드를 모두 포함한다.

| 필드 | 자료형 | 의미 |
|---|---|---|
| `id`, `name` | 문자열 | 월드의 ID와 표시 이름 |
| `state` | 문자열 | `play`, `dialogue`, `stats`, `inactive` 등의 씬 상태 |
| `active` | 불리언 | 해당 실행 인스턴스에서 선택된 월드 여부 |
| `width`, `height` | 정수 | 맵 크기, 각각 1 이상 100000 이하 |
| `kills` | 정수 | 해당 월드의 누적 처치 수, 0 이상 |
| `villages` | 배열 | `{ "id": "town-a", "name": "마을 A" }` 형태의 마을 정의 |
| `npcs`, `monsters` | 배열 | 현재 NPC와 몹 슬롯의 전체 목록 |

NPC와 몹은 다음 공통 엔티티 형식을 사용한다.

| 필드 | 자료형 | 의미 |
|---|---|---|
| `id` | 문자열 | 월드 내에서 NPC와 몹 전체에 걸쳐 중복되지 않는 ID |
| `villageId` | 문자열 | 소속 마을 ID. 마을에 속하지 않으면 빈 문자열 |
| `kind`, `behavior`, `state` | 문자열 | 종류, 행동 유형, 현재 상태 |
| `position` | 객체 | 유한한 숫자인 `x`, `y`, `z`를 가진 월드 좌표 |
| `alive` | 불리언 | 현재 생존 여부 |
| `health`, `maxHealth` | 숫자 또는 null | 체력이 없으면 둘 다 null. 값이 있으면 `0 <= health <= maxHealth`, `maxHealth > 0` |
| `respawnSeconds` | 숫자 | 남은 재생성 시간, 0 이상. 재생성 대기가 아니면 0 |

ID와 `kind`, `behavior`, `state` 값은 영문·숫자와 `_`, `-`, `.`, `:`를 사용하고 길이는 1~128자로 제한한다. `villageId`만 빈 문자열을 허용한다. 표시 이름은 비어 있지 않은 문자열이며 최대 160자다. 월드는 메시지당 최대 32개, 마을은 월드당 최대 128개, NPC와 몹은 각각 월드당 최대 10000개다. 숫자 카운터와 메시지 번호는 JavaScript가 정확하게 표현할 수 있는 정수 범위까지 허용한다.

집계 수치는 수신 서버가 엔티티 목록에서 계산한다. 요청에 집계 필드를 추가해도 서버 계산을 대체하지 않는다. 조회 응답의 월드와 마을에는 `counts`가 추가되며 `npcCount`, `npcAlive`, `monsterAlive`, `monsterSlots`, `monsterRespawning`을 포함한다. `monsterRespawning`은 `alive=false`인 슬롯 수이며 대기 시간이 정지한 슬롯도 포함한다.

`sourceId + instanceId`를 인스턴스 키로 사용한다. 해당 인스턴스의 `sequence`가 이전 값보다 클 때만 전체 상태를 교체한다. 같거나 작은 번호는 `200 { "accepted": false }`로 응답하며 연결 시간을 갱신하지 않는다. 더 큰 번호가 정상 수신되면 `200 { "accepted": true }`를 반환한다. JSON 또는 UTF-8 오류는 400, 용량 초과는 413, 지원하지 않는 콘텐츠 형식은 415, 규격 오류는 422를 반환하며 마지막 정상 상태를 보존한다. 최대 64개 인스턴스를 보관하고, 가득 찬 경우 오프라인 인스턴스를 먼저 제거한다. 모든 인스턴스가 온라인이면 새 인스턴스 요청에 503을 반환한다.

엔티티가 다른 마을로 이동하면 다음 스냅샷에서 `villageId`를 변경한다. 월드가 해제되거나 엔티티가 제거되면 다음 전체 목록에서 제외한다. 몹이 일시적으로 죽은 경우는 목록에 슬롯을 유지하고 `alive=false`로 전달한다.

## 다른 프로젝트의 연결

각 프로젝트에서 실제 게임 상태를 공통 월드·마을·엔티티 구조로 변환하는 어댑터를 만든 뒤 동일한 수신 주소로 전송한다. `sourceId`는 프로젝트마다 구분하고 `instanceId`는 프로세스를 재시작할 때 새로 발급한다. 같은 프로젝트를 여러 번 실행하면 화면에서 인스턴스별로 구분한다.

현재 게임 송신기는 Windows WinHTTP를 사용하며 목적지를 `127.0.0.1`로 제한한다. 외부 프로젝트가 다른 PC에서 실행된다면 해당 상태를 로컬 수신 서버로 전달하는 중계 어댑터가 추가로 필요하다. 원격 수집 방식은 최종 통합 방식이 결정된 후 정할 수 있다.

월드 이동 기능을 구현할 때 월드·마을·엔티티 ID는 유지하고, 모니터링 어댑터의 소속 정보만 갱신하면 된다. 여러 프로젝트를 하나로 합치거나 프로세스를 분리하는 방식 모두 이 수신 규격에 연결할 수 있다. 프로세스 간 이동을 추적할 전역 엔티티 ID, 소유권 이전, 이동 요청과 완료 이벤트는 추후 통합 설계에서 정해야 한다. 현재 모니터는 상태를 관측하며 게임 조작이나 월드 이동 요청을 처리하는 API는 제공하지 않는다.

## 포트와 게임 설정

| 설정 | 기본값 | 용도 |
|---|---|---|
| `GAME_MONITOR_ENABLED` | 켜짐 | `0`이면 게임의 모니터링 송신 비활성화 |
| `GAME_MONITOR_SOURCE` | `gsw-base-project` | 프로젝트 ID 지정 |
| `GAME_MONITOR_PORT` | `8765` | 로컬 수신 포트 지정 |

게임 설정은 실행 시 환경 변수에서 읽는다. Visual Studio로 실행한다면 프로젝트 디버깅 환경 변수에 지정한다. 셸에서 실행한다면 게임을 시작할 셸의 환경 변수로 지정한다. 포트를 바꿀 경우 서버 실행 인자와 게임 환경 변수를 맞춘다.

```powershell
node .\Monitoring\server.js 8766
```

위 서버에 연결하는 게임은 `GAME_MONITOR_PORT=8766`으로 실행하고 브라우저는 `http://127.0.0.1:8766`으로 접속한다. 올바르지 않은 프로젝트 ID나 포트를 지정하면 송신을 비활성화하고 게임 콘솔에 `monitor.config_invalid`를 출력한다. 초기화, 연결 성공·실패, 종료 역시 게임 콘솔에 `[monitor] monitor.*`로 표시한다. 현재 게임에는 이전의 분석 로그 모듈이 없으므로 파일 로그 의존성 없이 동작한다.

## 확인 절차

수신 처리 테스트는 리스너를 열거나 게임을 실행하지 않고 다음 명령으로 실행한다.

```powershell
node --test .\Monitoring\server.test.js
```

수동으로 수신 서버를 확인하려면 서버를 실행한 뒤 다른 PowerShell 창에서 예제 메시지를 보낸다.

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8765/api/snapshot -Method Post -ContentType 'application/json; charset=utf-8' -InFile .\Monitoring\example-snapshot.json
```

HTML에서 예제 NPC 1명, 몹 2개 슬롯 중 생존 1개와 재생성 대기 1개를 확인한다. 반복해서 상태를 갱신하려면 예제의 `sequence`를 증가시킨다. 한 번만 보내면 5초 뒤 오프라인으로 전환된다. 서버의 `GET /api/health`는 수신 서버 동작 여부, `GET /api/state`는 전체 최신 상태를 JSON으로 반환한다.

게임을 빌드한 후에는 다음 항목을 확인한다.

1. 마을 플레이 중 NPC 8명과 몹 0개가 표시되고, NPC 위치가 지도 데이터와 일치하는지 확인한다.
2. NPC 대화 중 대상 NPC가 대화 상태이고 나머지 NPC가 정지 상태인지 확인한다.
3. 게임 인트로에서 `1`을 누르거나 튜토리얼 엔딩을 진행해 제1레벨로 이동한다. 마을은 비선택으로 남고 제1레벨 몹 16개 슬롯이 표시되는지 확인한다.
4. 제1레벨에서 몹을 처치하면 생존 수가 줄고 재생성 대기 시간이 표시되며, 재생성 후 다시 생존으로 바뀌는지 확인한다. 능력치 화면과 쓰러짐 상태에서 생존 몹 상태가 정지로 바뀌는지도 확인한다.
5. 서버를 종료해도 게임이 계속 진행되고, 다시 서버를 켜면 새 상태가 수신되는지 확인한다.
6. 게임을 종료하면 5초 후 인스턴스가 오프라인으로 표시되고 상단 합계에서 제외되는지 확인한다.
